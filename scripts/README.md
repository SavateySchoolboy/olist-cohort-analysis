# Загрузка отзывов Olist

`import_reviews.psql` загружает исходный `olist_order_reviews_dataset.csv` в существующую таблицу `public.order_reviews`, сохраняя пять полей: `review_id`, `order_id`, `review_score`, `review_creation_date`, `review_answer_timestamp`.

Новый CSV не создаётся. Сначала PostgreSQL читает все семь столбцов исходного файла во временную таблицу, затем переносит только нужные поля в основную. Это позволяет обработать запятые, кавычки и переносы строк внутри комментариев штатным CSV-парсером PostgreSQL.

## Перед запуском

1. Установить PostgreSQL с утилитой `psql` и запустить сервер.
2. Подготовить базу `olist` и таблицу `public.order_reviews` с пятью столбцами из раздела 7 файла `01_create_tables.sql`. В уже заполненной базе весь скрипт создания таблиц повторно не запускать.
3. Положить исходный файл по пути `data/raw/olist_order_reviews_dataset.csv`. CSV исключены из Git через `.gitignore`; после скачивания репозитория данные нужно получить отдельно.
4. Открыть терминал в корне репозитория, где находится `01_create_tables.sql`. Относительный путь в `\copy` отсчитывается от текущей папки терминала.

Скрипт загружает только отзывы. Он не создаёт базу, основную таблицу и не импортирует остальные файлы Olist.

## Запуск в Windows CMD

Для текущей установки PostgreSQL 18:

```cmd
cd /d D:\projects\olist-cohort-analysis
"C:\Program Files\PostgreSQL\18\bin\psql.exe" -X -h localhost -p 5432 -U postgres -d olist -f scripts/import_reviews.psql
```

На другом компьютере заменить путь к проекту и при необходимости путь к `psql.exe`, адрес, порт, пользователя и название базы. Если `psql` доступен в PATH:

```sh
psql -X -h localhost -p 5432 -U postgres -d olist -f scripts/import_reviews.psql
```

Пароль вводится в приглашении PostgreSQL. Сохранять его в скрипте или репозитории не нужно. Ключ `-X` отключает пользовательский файл настроек psql для более предсказуемого запуска.

## Повторный запуск и ошибки

**Успешный запуск полностью заменяет данные только в `public.order_reviews`.** Не применять скрипт к таблице с ручными изменениями, которые нужно сохранить. Повторный запуск не добавляет ещё одну копию всех отзывов; повторы, уже присутствующие в исходных данных, сохраняются.

Загрузка и замена выполняются в одной транзакции. `ON_ERROR_STOP` останавливает выполнение при первой ошибке; при закрытии подключения незавершённая транзакция откатывается. Например, ошибка чтения CSV не оставляет частично обновлённую основную таблицу. `TRUNCATE` используется без `CASCADE`; если зависимости не позволяют очистку, скрипт завершится ошибкой.

При успехе ожидаются сообщения `COPY 99224`, `INSERT 0 99224`, `COMMIT`, затем результат:

| imported_rows | min_score | max_score |
|---|---|---|
| 99224 | 1 | 5 |

В DBeaver можно дополнительно выполнить:

```sql
SELECT count(*), min(review_score), max(review_score)
FROM public.order_reviews;
```

## Проверка перед коммитом

На отдельной тестовой базе создать таблицу из раздела 7, выполнить загрузку и сверить итоговые значения. Повторить запуск: число строк должно остаться 99 224. Такая проверка ещё не выполнена для сохранённого скрипта; последовательность команд ранее была успешно выполнена вручную.

Исходный CSV изменять не требуется. Скрипт запускается утилитой `psql`: команда `\copy` не является обычным SQL-запросом DBeaver. Справка: [PostgreSQL psql](https://www.postgresql.org/docs/18/app-psql.html#APP-PSQL-META-COMMAND-COPY).
